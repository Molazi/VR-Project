# Правила работы с Git и GitHub

## Основные правила

1. **Никогда не пушим напрямую в `main`.**
   Все изменения попадают в `main` только через Pull Request.

2. **Каждая задача - отдельная ветка.**
   Например:

   ```
   feature/terrain-smoothing
   feature/water-undo
   fix/water-visual
   ```

3. **Один логический шаг - один коммит.**
   Не нужно делать коммит после каждой изменённой строки, но и складывать всю работу за несколько дней в один `commit` тоже НЕ НАДО.

4. **Перед началом новой задачи обновляем `main` через git pull**
   Новую ветку создаём именно от актуального `main`.

5. **После завершения логического этапа делаем commit и push.**

6. **Готовую задачу отправляем через Pull Request в `main`.**
   Перед merge желательно проверить изменения и убедиться, что в PR нет случайных файлов.

7. **После merge удаляем ветку.**
   Ветка больше не нужна после того, как её изменения попали в `main`.

8. **Не коммитим Unity-кэш и автоматически создаваемые файлы.**
   Например:

   ```
   Library/
   Temp/
   Logs/
   UserSettings/
   ```

   и другие файлы, которые уже исключены через `.gitignore`.

9. **Не работаем одновременно над одной сценой без договорённости.**
   Unity-сцены и некоторые Prefabы могут конфликтовать при одновременном редактировании.

10. **Если что-то непонятно - лучше спросить**
    Особенно не используем `reset --hard`, `force push` и удаление файлов, если не понимаем, что они делают.

*Если возникли какие-то вопросы или вы в чем-то не уверены, то лучше лишний раз написать мне.*

---

## Начало новой задачи

Сначала обновляем `main`:

```bash
git switch main
git pull
```

Затем создаём новую ветку:

```bash
git switch -c feature/название-вашей-задачи
```

Например:

```bash
git switch -c feature/terrain-smoothing
```

---

## Во время работы

Периодически проверяем изменения:

```bash
git status
```

Перед коммитом добавляем **только нужные файлы**:

```bash
git add <только необходимые изменённые файлы>
```

Проверяем, что именно попадёт в коммит:

```bash
git diff --cached
```

Если всё правильно:

```bash
git commit -m "краткое описание изменения ПО УНИВЕРСАЛЬНЫМ ПРАВИЛАМ"
```

Примеры:

```text
feat: add terrain smoothing
fix: correct brush radius
refactor: simplify terrain deformation
```

После этого отправляем ветку на GitHub:

```bash
git push -u origin feature/название-вашей-задачи
```

---

## Pull Request

После `push` создаём Pull Request:

```text
ваша ветка → main
```

В PR должно быть понятно:

* что было сделано;
* зачем это было сделано;
* какие части проекта были изменены.

После проверки и merge ветку можно удалить.

---

## Если Git показывает ошибку

**Не удаляйте файлы и не используйте команды наугад.**

Сначала сохраните текст ошибки и напишите мне.
